## 이 사이트의 구조적 한계

단일 페이지 앱이다. 제품 616개가 `<script type="application/json">` 안에 있고
표는 JS 가 그린다. 그래서 **크롤러가 읽는 가시 텍스트가 1,730자뿐**이었다

## '없음'과 '미탐지'를 절대 섞지 말 것 — 2026-08-30 사고 정정

처음 만든 `no-aspartame` / `no-erythritol` / `no-caffeine` 페이지는 **탐지되지 않은
제품을 '없는' 제품으로 묶었다.** 실제로는 절반 가까이가 원재료를 혼합제제로
뭉뚱그려 놓아 판단할 수 없는 제품이었다.

|페이지|'없음'으로 주장했던 수|그중 확인 불가|
|---|---:|---:|
|아스파탐 없음|563|312 (55%)|
|에리스리톨 없음|350|191 (55%)|
|카페인 없음|500|240 (48%)|

아스파탐은 페닐케톤뇨증 때문에 피해야 하는 사람이 있다. 잘못된 목록은 건강
위험이다. 그래서 부정형 목록은 **반드시 두 구획으로 쪼갠다**:

1. `○○ 없음이 확인된 N개` — 원재료가 투명하고 해당 성분이 없는 제품
2. `확인할 수 없는 M개` — 혼합제제로 가려져 단정할 수 없는 제품 (빨간 경고 문단 병기)

제목·직답 문단에도 두 숫자를 함께 쓴다. `_is_opaque()` 가 이 판정을 담당하고
`seo_landing_specs()` 의 `split()` 이 쪼갠다. **새 부정형 랜딩을 추가할 때
`negative()` 헬퍼를 쓰면 이 구조가 강제된다.**

## 제품별 상세 페이지 — 2026-09-03 추가

제품 하나가 URL 하나를 갖는다: `docs/p/<슬러그>.html` 616장. 사이트맵 8 -> 624 URL.
"들어와서 검색하게" 만들면 검색 결과에 애초에 안 걸리기 때문이다.

- **슬러그는 한글**이다 (`p/코카콜라-제로.html`). 한국어 검색에서 URL 키워드 일치가
  크고 공유할 때 읽힌다. **URL 로 쓸 때는 `slug_url()` 로 퍼센트 인코딩한다** —
  사이트맵 규격이 요구하고, raw UTF-8 URL 은 클라이언트가 그대로 요청하지 못한다.
- **제품명이 바뀌면 URL 도 바뀐다.** 유통명 반영으로 실제로 바뀐 적이 있다. 그때는
  이전 URL 이 404 가 되므로 이름 변경은 사이트맵 재제출(`--mode ping`)과 함께 한다.
- 각 장의 구조: 직답 문장 -> 요약 그리드 -> 신고 원재료 전문 -> 판매처 표시원재료
  -> 일반판 비교 -> 배합 이력 -> 등급 근거 -> 같은 제조사·같은 등급 링크.
  가시 텍스트 중간값 1,190자로 thin page 가 아니다.
- `Product` + `BreadcrumbList` JSON-LD. 열량·당류는 `additionalProperty` 로 넣는다
  (`NutritionInformation` 은 Product 에 유효하지 않다).
- **감미료와 당류 토큰을 분리해 말한다.** `_sweetener_rows()` 가 `(감미료, 당류)` 를
  돌려준다. 나랑드사이다 제로는 착향용 레몬농축과즙 때문에 당류 토큰이 잡히지만
  실측 당류 0g, 등급 B 다. "농축과즙이 들어 있습니다"를 감미료 문장에 섞으면 거짓이다.
- **조사는 `_josa()` 로 자동 선택한다.** 하드코딩하면 반드시 틀린다 — '아스파탐가',
  '815사이다은' 이 실제로 배포됐다.

### `.gitignore` 함정 — 616장이 404 였다

`!docs/*.html` 글롭은 **하위 디렉터리를 잡지 못한다.** `docs/p/` 616장이 전부
커밋에서 빠져 라이브에서 404 였다. `!docs/p/*.html` 을 따로 넣어야 한다.
새 하위 디렉터리를 만들면 예외를 반드시 추가하고 `git ls-files docs/<dir> | wc -l` 로
확인할 것.

### 표 없는 페이지에 필터형 검색을 붙이지 말 것

`_FINDER_FILTER` 는 페이지 안의 `<table>` 을 거른다. 제품 상세에는 표가 없어서
"0개 표시 중 (전체 0개)"만 뜨는 죽은 검색창이 616장에 배포됐다. 지금은
`_FINDER_JUMP`(= `products.html` 로 보내는 GET 폼)를 쓴다. `has_table=False` 로
`_static_page()` 를 부르면 자동으로 갈린다. GET 폼이라 JS 없이 동작하고
목록 쪽은 `?q=` 를 읽어 프리필한다.

## 이름은 '전부 통일'이 답이 아니다 — 2026-09-03

세 종류를 구분한다. 사이트 이름만 통일하고 엔티티 이름은 일부러 다르게 둔다.

|종류|슬롯|통일?|
|---|---|---|
|사이트 이름|`og:site_name`, `WebSite.name`, `<title>` 접미|**반드시 일치**. 검색엔진이 교차 검증하고, 갈리면 판단을 포기하고 도메인명을 쓴다|
|데이터셋 이름|`Dataset.name`|아니요. Dataset Search 는 **서술적 제목**을 선호한다. `alternateName` 으로 사이트명과 연결한다|
|발행 주체|`publisher`, `creator`|**절대 아니요**. 사이트 이름과 같은 문자열을 쓰면 Knowledge Graph 에서 사이트와 조직이 뭉개지고 `sameAs` 로 검증할 대상이 사라진다|

사이트 이름은 `_STATIC_PAGE_SITE_NAME` 상수와 `WebSite.name` 을 함께 고친다.
`SiteIdentityTests` 가 세 슬롯 일치와 엔티티 이름 분리를 동시에 막는다.

### 고친 두 가지

- **`WebSite` 노드가 없었다.** 사이트명을 주장하는 정식 슬롯이 비어 있었고
  `Dataset` 은 site name 소스가 아니다. `@graph` 에 `WebSite`(#website)를 넣고
  `Dataset` 은 `isPartOf` 로 연결했다.
- **`publisher` 가 실체 없는 `Organization`('대체당 제로 음료 티어')이었다.**
  `creator` 는 `Person gulf1324` 인데 발행 주체만 가짜 조직이었고, 사이트 이름과
  문자열이 같아 엔티티가 겹쳤다. `Person`(#author)로 정정하고 `@id` 로 공유한다.

### SearchAction 은 선언 전에 URL 이 동작해야 한다

`products.html?q=` 는 이미 동작하는 GET 검색이었는데 선언만 빠져 있었다
(sitelinks searchbox 후보). **`urlTemplate` 의 파라미터 이름이 `_FINDER_JS` 의
프리필(`get('q')`)과 같아야 한다** — 다르면 검색창이 붙어도 결과가 걸러지지 않는다.
테스트가 둘을 함께 검사한다.

## 색 팔레트는 파이썬 상수 하나다 — 2026-09-03 정정

`_PALETTE_CSS` 를 리포트(`_HTML_TEMPLATE` 의 `__PALETTE__` 자리)와 정적 페이지
(`_STATIC_CSS`)가 **같은 문자열로 공유**한다. 예전에는 복사본을 두었다가 다크모드가
리포트에만 먹는 사고가 났다. 색을 바꿀 때는 `_TOKENS_LIGHT` / `_TOKENS_DARK` 만

## 정적 페이지의 검색·정렬은 메인 리포트 규약을 재사용한다

표는 빌드 때 HTML 로 전부 렌더되고, 스크립트는 **행을 숨기거나 순서만 바꾼다.**
크롤러가 보는 내용은 변하지 않는다 (점진적 향상).

- 정렬 마크업은 메인 리포트와 같은 `th[data-key]` + `data-sort`(tier/num/size/text)
- 화살표도 같은 방식이다: `th.sorted::after{content:" " attr(data-dir)}`.
  **초기 상태에는 `sorted` 클래스도 `data-dir` 속성도 없다** - 정렬하지 않은 표에
  화살표가 떠 있으면 거짓 정보다
- 표가 두 개인 페이지(확인된/확인 불가)는 **각 표가 독립적으로** 정렬된다
- **데이터 없는 칸은 오름/내림과 무관하게 항상 맨 뒤로.** '없음'을 '가장 큼'으로
  두면 열량 내림차순 첫 화면이 공란으로 찬다
- 정렬은 필터 상태를 건드리지 않는다 (숨긴 행도 같이 재배치되므로 검색 결과가 유지된다)

## 정적 페이지 순서는 고정이다

`h1` → **요약** → **읽는 법** → 기준일 → 표.

읽는 법을 표 아래에 두면 수백 행을 지나야 '절반은 확인 불가' 같은 한계가 보인다.
**읽는 사람이 못 보는 경고는 없는 경고다.** 답변엔진도 첫 화면에서 답을 추출하므로
한계와 기준을 위에 두는 것이 인용 품질에도 맞다.

이 순서는 `_static_page()` 가 강제한다 (`summary`·`howto` 를 본문과 분리된 인자로
받는다). 본문에는 표와 소제목만 들어간다.

## 지켜야 하는 규칙

- **가시 FAQ 와 FAQPage LD 는 `_FAQ` 상수 하나에서 만든다.** 둘을 따로 쓰면
  글자가 어긋나고, 가시 텍스트와 다른 구조화 데이터는 스팸 판정 위험이다
- **ItemList LD 의 항목은 화면 표에 실제로 있는 제품만** 넣는다 (상위 100개 제한)
- **직답 문단은 첫 화면에.** 답변엔진은 페이지를 요약하지 않고 답이 되는 문장을
  추출하므로, `요약` 아래 첫 문장이 그 자체로 답이 되어야 한다
  (`… 없는 것은 <b>251개</b>입니다`). **`결론부터` 같은 도입부는 붙이지 않는다** -
  제목이 이미 '요약'이라 같은 말을 두 번 하는 것이고, 추출됐을 때 군더더기가 된다
- **열량·당류에는 항상 기준을 붙인다** (100mL당). 기준 없는 숫자는 답변엔진이
  신뢰 판정에서 감점하고, 라벨(한 병 기준)과 달라 보여 사용자도 혼동한다
- **`write_seo_files()` 는 `records` 를 필수로 받는다.** 빼먹으면 사이트맵이 조용히
  1 URL 로 줄고 정적 페이지가 낡은 채 남는다. 그래서 기본값을 없애고 예외를 던진다
- **배포는 `publish_docs()` 한 곳으로만 한다.** `--mode build --docs-html docs/index.html`
  또는 `--mode sync` 어느 쪽이든 리포트 복사·정적 페이지·llms.txt·사이트맵·IndexNow
  키 파일이 같은 시점으로 함께 갱신된다. 손으로 복사하지 말 것
- **정적 페이지에도 GA 를 넣는다.** 측정 없는 랜딩은 반쪽이다
- robots.txt 에서 AI 크롤러를 막지 말 것. 공개 정부 데이터이고 산출 코드도 MIT 다

## IndexNow

**키는 코드가 스스로 찾는다.** 환경변수 `INDEXNOW_KEY` 가 있으면 그것을 쓰고,
없으면 `docs/` 에서 **파일명(확장자 제외)과 내용이 같은 `.txt`** 를 키로 인정한다.
키 파일은 사이트 루트에 공개되도록 설계된 값이라 저장소에 그대로 들어가고,
한 번 배치해 두면 환경변수 없이 계속 동작한다.

`llms.txt`·`robots.txt` 처럼 무관한 텍스트 파일을 키로 오인하지 않는지는
`IndexNowKeyTests` 6개가 지킨다.

```bash
python zero_soda_scan.py --mode ping    # 사이트맵의 URL 전량 통보
```

`sync` 에도 배선돼 있어 월간 갱신 때 자동 통보한다. 응답 202 는 키 검증 대기,
200 은 검증 완료다. 둘 다 접수 성공이다.

Google 은 IndexNow 를 소비하지 않으므로 **사이트맵 lastmod 정확성으로 승부**한다.
